# 公开前敏感信息检查与维护

## 本次检查范围

2026-11-10，在将仓库由私有改为公开前，检查了：

- 所有分支、标签和可达 Git 提交历史中的文件内容。
- 当前准备提交的 README 和 AI Agent 接入文档。
- 已知现场部署凭据及部署标识的精确匹配、常见 API Token/私钥/真实函数 URL 模式。
- GitHub 自动检查日志，以及仓库发布附件和 issue 的现状。
- `.gitignore` 对私有配置、部署状态、账本、日志和构建结果的排除。

使用 Gitleaks v8.30.1，工具下载包经其官方发布校验和核验；扫描覆盖 Git 历史和暂存修改，启用输出脱敏，没有为本次扫描添加忽略规则。另做了针对已知现场数据的检查与人工文件检查。

**本次检查范围内未发现真实密钥、密码、节点令牌、实际函数 URL 或现场服务器地址。** 配置模板中的 `CHANGE_ME` / `YOUR_...`、单元测试中的固定假值仅用于示例和测试。

敏感扫描的原始报告保存在检查环境中，不将可能包含秘密的扫描报告上传到仓库。

## 哪些文件不能提交

- 腾讯云 SecretId/SecretKey/临时 Session Token。
- 真实 `agent.json`、部署配置、节点令牌和节点清单。
- 费用账本、连接日志、测试目标认证信息、Cookie 和完整业务响应。
- SSH/CA/其他私钥、真实 Proxifier 配置导出、含凭据的诊断包。

`.gitignore` 只影响未跟踪文件，不能清除已经提交过的秘密。不要为了提交配置而使用 `git add -f`。示例凭据应保持显然不可用于实际登录的占位值。

## 后续改动建议

提交前审阅 `git diff --cached`；发布前扫描全部历史，而不只扫描工作目录。可使用：

```bash
gitleaks git --log-opts='--all' --redact=100 --ignore-gitleaks-allow .
gitleaks git --staged --redact=100 --ignore-gitleaks-allow .
```

如果将来发现真实秘密进入 Git，先撤销或轮换对应凭据，再清理历史和相关副本、附件、日志；仅删除当前文件不足以处理历史泄漏。

AI Agent 的代理凭据应注入执行器的 Secret/环境变量，不放进模型提示词、任务记录或命令回显。此网络出口不内置测试目标授权判断，使用方仍须在执行器实施授权范围和目标限速。
